## Implemented mechanisms

1. **Owned practice log, personal and never desk-scoped.** Additive `practice_timers` (one row per user: `idle|running|paused`, `accumulated_ms`, `pause_count`, `version`) and append-only `practice_sessions` (`human_declared` receipts + `imported_unverified` archives) with a `UNIQUE(user_id,day,version)` index, an owner index and an immutability trigger. SQL UPDATE facts immutable (FK nullification the only exception); owner deletion cascades. Not sealed against database-admin tampering. **No `/practice` route accepts an `account_id`**, so a practice record cannot be attributed to an account or a desk and cannot bind M64's routine or M107's intention. Nothing is backfilled, defaulted or carried over between days.
2. **Elapsed server running time is the only measurement.** `elapsed_source:'server_running_time'`; a pause gap does not count; `pause_count` is threaded onto the receipt. Presets 300/600/900/1800/3600 s, or the trader's own `hours`/`minutes`/`seconds` (60–7200 s, at most 2 hours). Bell intervals are the elapsed-time markers `0/60/120/300/600`, listed strictly inside the measured running time. A session open for more than 24 hours cannot be completed as one session: 409 with nothing written, cancel it instead.
3. **One transactional write contract.** Every action carries the displayed 64-hex `revision`; it is compared and set inside one transaction, so a stale, unknown, malformed or wrong-state action is 409 with **nothing written** and there is an explicit reload. No caller day, clock, elapsed time, source, owner or authority is accepted in any body; an unknown key is refused with a message naming what is not accepted.
4. **Records, not results.** Completing writes **one** immutable receipt (measured time, markers reached, `pause_count`, the trader's own note ≤2000, the optional intention with its framing and cues) and it is recorded exactly as it happened — a short session, or one completed early, is **not** a failure. Day/history/progress count **readable `state:'recorded'` rows only**: a stored receipt the app cannot read back is reported `unavailable`, is never counted as a session or a measured second, and is never repaired or invented. Progress counts records (`counts_are_records_only:true`, `target:null`, `score:null`, `days_with_recorded_session`, `consecutive_days_with_a_recorded_session_ending_on_to`) with no goal, percentage or streak pressure.
5. **No authority anywhere.** No score, percentage, adherence tally, readiness, gate or permission over entries/signals/risk/cap/routine/core/grades/history, and no change to any of them. The briefing and the owned journal day carry the same practice object and the journal-day read answers `unavailable` rather than failing its host surface; a foreign trader sees nothing.
6. **Honest toolkit.** Seven items in the three episode groups (`reboot`/`rewire`/`recovery`), each with steps, a note and an explicit source label (`episode_example` vs `curated_app_text`); every item that the episode describes with an effect the app cannot verify says so in the item itself (the parasympathetic claim is attributed and disclaimed); the breathing text stays text — the app times nothing there and verifies no bodily effect.
7. **Optional intention reuses M107's contract.** Free text is stored exactly as written as `unverified_free_text` (never `process_template`), with the same bounded classifier cues and warnings; an amount and outcome asserted in the same non-negated sentence is refused `practice_outcome_target` 400 with nothing written; an all-blank or whitespace-only line means **no intention** rather than an error (the optional field is optional); and no trading surface reads it.
8. **Actual daily surfaces.** One shared day card on the Dashboard and the owned Journal day with two doors (*Open the practice timer*, *Progress (records, not results)*): timer modal (presets or custom, bells, ambience, toolkit, intention), the actions (`start`/`pause`/`resume`/`complete and record`/`cancel (writes nothing)`/reload), the readonly history and the progress view. Typed state lives in module-level draft state so a preset click cannot discard a typed intention or a chosen bell/ambience; the draft is cleared when a session is recorded. Escaped text, explicit reload with 409 handling, Settings carries the archive warning. No chart/provider fetch.
9. **Portable history, finance unaffected.** Full JSON backup carries `practice_sessions:{version,records,unavailable_records}`; restore labels every copy `imported_unverified`, keeps the original day, clock, elapsed time and id as history, never counts it as this app's measured running time, appends on repeat import (no upsert or dedupe) and warns on malformed optional entries while the financial import stays legal. A missing store leaves the financial backup legal with an `unavailable` marker.

## Initial errors kept, not erased by closure

- **Two real app faults, found by the new hardening probe and fixed in the app.** The first hardening run measured **24/3**: (a) an all-blank/whitespace practice intention was refused with a 400 instead of meaning "no intention", which made the optional line mandatory in practice; and (b) the day view and progress totals counted stored rows the app could not read back as recorded sessions and measured seconds. Fix: the blank guard in the module's `intention()`, and `recorded`/`archives`/`seconds` computed from **readable** rows only in `viewOn` and `progress`. The probe was then rewritten (hoisted awaits; a consumed-revision replay that asserts 409 and no second write) and the cohort is **28/0**; the pre-hardening arm now preserves both original failures as measured control evidence.
- **The pure probe's contract line was corrected to the app's honest behaviour, not the reverse.** It had asserted that an empty string is refused; the app's rule is that a blank optional line means "no intention". The probe now asserts both (`a non-string`/over-cap/control characters refused, blank maps to `null` framing and cues), and the pre-hardening control measures the superseded refusal as exactly one failing assertion (**70/1**). Guards were not weakened for it.
- **Migration-probe fixture traps, fixed probe-side.** `POST /trades` with `status:'open'` is refused by the mandatory routine on a fresh account (the migration parent is a fresh database), so the parent now writes real **record-only closed** history, which is never gated and still exercises the emotion, journal and execution-review tables; the same tree then answers the live-entry attempt identically, so the "practice changes nothing about admission" assertion compares the upgraded app's answer with the parent's own answer. `progress` legitimately refuses a period that runs past today (`A future UTC day cannot be read as a day that happened.`), so the probe uses a past-or-today window. A second `start` while a session is open is refused 409 by state *before* the intention is validated, so the money-target refusal is measured on an idle timer and then the same, unchanged revision is used to start the real session — one extra assertion that a refused write does not even bump the timer version. The state-gate view's `age_minutes` is a live clock read, so the end-of-run comparison asserts the inherited **facts** byte-identical and allows only the view's own clock-derived fields to move.
- **UI-probe trap fixed probe-side and in the app.** jsdom fires nothing for a programmatic `node.value` assignment, so the probe dispatches `input` (a phantom "empty intention" refusal came from this). The same investigation exposed a real UI fault: a preset click redrew the modal and discarded a typed intention, because the typed state lived only in the DOM. Fix: module-level draft state (`P._draft` for the intention plus the chosen bell/ambience) survives redraws, is written by `input`/`change`, and is cleared when a session is recorded. The archive assertion also had to read the modal through the DOM after calling the (async, return-value-not-a-node) history helper, and to accept a Close button in a readonly modal.
- **A stray `;` inside a SQL comment** makes the libSQL batch refuse with `SQLITE_UNKNOWN_0`; the schema comments are semicolon-free. A timer view read `row.framing` where the column is `intention_framing`; caught by the API probe before any delivery claim. `POST /import/json` answered 503 because the shared `importTradesWithMedia` signature defaulted a new `practice` parameter out of scope; fixed at the single call site.
- Third-party OHLCV fixtures are gitignored and re-fetched per session; `npm ci` reproduces dependencies. The M107 parent tree used by the migration probe is rebuilt from the committed `8a2cfd5` Git tree by the runner and asserted against `parent-source.json`, so no historic working directory is required.
